# 访问控制与分流策略

全局名单和命名策略都是包名集合。界面在 `app` 的 `AccessControlActivity` 与 `AppsStrategyActivity`，控件在 `design`，存储在 `service` 的 `ServiceStore`。全局名单只有一个入口：应用分流的「默认回退」。网络设置不再放访问控制模式或包列表。

## 谁会出现在列表里

`loadAccessControlApps` 跳过本应用。其余已安装包要声明 `INTERNET`，或者 UID 小于应用 UID。系统应用记入系统集合。包名出现在国内目录里的，记入国内集合。包名出现在浏览器目录里的，只记入浏览器集合，不再计入系统集合或国内集合。

「隐藏系统应用」只决定系统应用的行是否显示。三个集合的成员不受这个开关影响。

全选和反选只改当前可见包。看不见的已选包，包括关掉显示时的系统应用，以及没有 `INTERNET` 因而不进列表的包，保持原样。剪贴板导入只替换可见包里的选择，并保留看不见的已选包；剪贴板里没有已安装包时，选择集不变。全不选仍清空整个集合。应用集合的编辑草稿绑定打开时的集合；目标换成另一份时草稿作废，保存和删除作用在当前草稿上。

国内目录是 `app/src/main/res/raw/domestic_packages.txt`，浏览器目录是 `app/src/main/res/raw/browser_packages.txt`。两者都由 `RawPackageCatalog` 读取。行格式是 `包名`，`#` 后面是注释。包名要匹配目录加载器里的正则：第一段以字母或下划线开头，后续段可以以数字开头。不放进 `assets/`，因为那个目录会被 `:app:clean` 删掉。

浏览器目录同时收录国内和国外的网页浏览器，例如 Via、夸克、UC、Chrome、Firefox、Edge。包名里带 browser 的内容应用和文件管理器仍留在国内目录。已经勾选过的应用不会因为目录变更而自动取消。

集合成员默认在每次加载列表时按当前安装重新计算。后来安装的应用不会自动被选中。编辑里改过成员并确认固定之后，用保存的包名；新安装的应用不进入该集合，直到恢复自动计算。只改名称或说明不会固定成员。

## 编辑集合

编辑在访问控制页的弹层里完成。弹层分「基本信息 / 成员应用」两段：名称、说明、内置集合的固定状态和成员摘要放在基本信息；搜索、全选、清除、反选和成员表放在成员应用。保存按钮固定在弹层底部，两段共用同一份草稿。名称为空时保存会回到基本信息并标出错误。成员表包含可进入名单的全部已安装应用，不受「隐藏系统应用」和名单排序影响。打开时已经在集合里的应用排在前面。计数是这份列表上的勾选数和列表长度。正在搜索时，全选、清除和反选只作用于当前结果。

自定义集合的名称为空时不保存。从应用分流新建或编辑时，弹层关掉就回到应用分流。有未保存的修改时，关闭会先确认，这个确认不是破坏性的。

内置集合可以恢复自动计算。已经写进 `settings/app_sets.json`、但没有 `membershipFrozen` 字段的内置集合，仍当作已固定，不会自动改回目录。

## 集合点选

`design` 的 `appSetMembership` / `applyAppSetToggle`：

- 当前成员全部已选：点一次只取消这些成员。
- 未全选：点一次选中全部当前成员。
- 没有成员：行不可点。
- 部分选中时，勾选框换成 `ic_app_set_indeterminate`。Material Components 1.6.1 的勾选框没有半选状态 API。
- 副标题是已安装数与已选数。

保存下来的仍然是包名集合，不是集合 ID。

## 离开页面

返回回调直接 `finish()`。`defer` 里立刻把包名写入存储，然后返回。旋转或深色模式重建不写存储，已选包名从实例状态恢复。覆写和 Meta 的持久覆盖同样只在 `finish()` 写入，重建时从实例状态恢复。隧道重载和 WebDAV 同步由 `scheduleExitWork` 在返回之后做。

写入目标：

- 从某份分流策略进入时，更新那份 `AppsStrategyConfig`。窗口标题是该策略的名称。
- 否则更新全局 `accessControlPackages`。标题是「全局应用名单」。

分流策略页的标题是「应用分流」。默认回退卡的模式菜单写回全局 `accessControlMode`；应用图标打开不带 UUID 的名单页。没有生效策略时，这张卡是当前生效项；有生效策略时，卡下面写「仅在未选择分流策略时生效」。名单上方显示已选数量。

包名没有变化则不重载、不同步。有变化时，只有这份名单正在驱动已运行的隧道才重载：编辑的是生效中的策略，或者当前没有生效策略而编辑的是全局名单。全局模式也按同一判定处理。重载调用 `requestClashReload()`。

自动同步仅在已开启、有端点、用户名和密码都非空时调度。调度立即返回，同步在服务进程里防抖后执行。

## 分流策略的存储

`ServiceStore` 把策略列表写在应用文件目录的 `settings/app_lists_configs.json`。当前生效策略的 UUID 另存在偏好里。`TunService` 在有生效策略时使用那一份模式和包名；没有生效策略时才回退到全局 `accessControlMode` 和 `accessControlPackages`。这个选择由 `resolveAccessControl` 统一计算，主界面和访问控制页复用同一判定。UUID 指向的策略已不存在时按没有生效策略处理。
