# 004. 用户数据提交、名单投影、编辑会话和失败隔离

## Context

2026-10-24 的十六路审查在 Android 壳里留下一批已核对的缺陷。它们不是各自的特例，而是四条边界没守住：写入没有提交点、屏幕投影被写回成全部事实、编辑会话没有主人、一次失败拆掉无关能力。产品边界仍是 [愿景](../../docs/product/vision.md)：内核行为以 mihomo 子模块为准。这次只约束本仓库的壳、桥和发布顺序。

## Decision

1. **提交点。** 配置目录、地理库和预发布资产在新内容完整落地之前，保留上一份完整内容。校验或复制失败不留下半截正式文件，也不把成功提示给用户。`FetchAndValid` 在 `UnmarshalAndPatch`、provider 落盘和 `Parse` 都成功之后才替换正式文件。`ProfileProcessor.apply` 与 `update` 先把新目录准备好，再替换 `imported/`。GeoIP、GeoSite、ASN 只有写到规范文件名才提示成功并打上用户标记。预发布工作流在新 APK 成为 `Prerelease-alpha` 的已发布资产之前，不删除已有的该 Release。

2. **投影不是事实。** 访问控制的全选、反选和剪贴板导入只改当前可见包。隐藏的系统应用和没有 `INTERNET` 因而不在列表里的已选项保持原样。全不选仍清空整个集合。应用集合编辑弹层的草稿绑定本次打开的集合 id；目标 id 变了就丢弃草稿，保存和删除都作用在当前这份草稿上。

3. **编辑会话。** 访问控制的已选包名、覆写和 Meta 的持久覆盖在旋转或深色模式重建后仍在，且这次恢复不写存储。只有 `finish()` 的 `defer` 写回。同一字段的编辑在前一次尚未结束时不再打开第二层。无法按整数解析的端口确认不写回。未设置的 WebDAV 字段在没有新内容时仍是 null，不写成空字符串。

4. **失败隔离。** 代理页的重载、选节点、测速和切换模式失败只结束这次请求，不取消主界面的 `coroutineScope`。`CancellationException` 仍向外传递。HTTP 入站先保留旧监听，新地址绑定成功后再替换；失败不把包级 listener 写成失败结果。`VpnService.protect` 返回 false 时，这次拨号失败，不把未保护的 fd 送进隧道。

WebDAV 正文的 etag 未变仍跳过 GET。远端 `_sync.json` 里同一 uuid 的用量仍进入合并；上传 meta 写出合并后的用量，不用本地旧计数覆盖远端。

## Consequences

- 正面：半次成功不再表现为旧数据还在，或新数据已经生效。
- 负面：批量选择的范围是当前可见名单，不是已安装的每一个包。端口的非法文本不能靠确定键清掉覆盖，清空仍走空字符串或重置。
- 不在本次：mihomo 子模块内的协议、DNS 回退和重组缺陷。签名口令进日志、正式发布先推标签、fd 所有权两条路径不一致，留在审查方案里，不纳入这四条的实现。

## Alternatives Considered

- **把主界面改成 `supervisorScope`。** 能挡住子协程失败，但会改变仪表盘和其他壳的取消语义。只在代理页这四个请求上接住非取消异常。
- **在 `onDestroy` 提前写存储。** 重建也会销毁 Activity，会把未返回的编辑写成已提交。会话放进实例状态，写存储仍只在 `finish()`。
- **在本仓库改 mihomo 的传输和 DNS。** 与愿景里的内核边界冲突。壳只修正自己交给内核的写入、名单和拨号保护。
