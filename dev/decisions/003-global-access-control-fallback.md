# 003. 全局访问控制保留为默认回退

## Context

应用分流允许保存多份命名策略并选一份生效。`TunService` 在有生效策略时使用策略的模式和包名，没有生效策略时才使用全局 `accessControlMode` 和 `accessControlPackages`。

设置 > 网络仍提供“访问控制模式”和“访问控制应用包列表”。有生效策略时，这两项仍可编辑，但不会改变正在运行的隧道；页面只靠一句说明提示“由策略接管”。同时，应用分流的“默认回退”已经能编辑同一份全局名单，形成两个入口。用户因此容易认为访问控制失效。

## Decision

保留全局名单和全局模式作为默认回退，不强制每台设备都必须有生效策略。删除设置 > 网络里的两个访问控制入口，把全局模式和全局名单的唯一入口放到应用分流的“默认回退”卡：

- 默认回退卡的模式菜单写回 `accessControlMode`。
- 应用图标打开不带 UUID 的 `AccessControlActivity`，编辑 `accessControlPackages`。
- 没有生效策略时，默认回退是当前生效项；有生效策略时，卡下注明“仅在未选择分流策略时生效”。
- 全局模式或名单变化时，只有它们正在驱动已运行的隧道才重载。
- 再点已生效的策略保持选中，不再隐式切回全局回退。

`resolveAccessControl` 统一计算结果，`TunService`、主界面和应用分流页复用同一判定。

## Consequences

- 正面：访问控制只有一个入口，设置页不再展示被策略覆盖的伪设置项。
- 正面：没有策略时仍能按应用分流，不需要先创建策略。
- 正面：WebDAV 的 `accessControlMode` 和 `accessControlPackages` 字段保持兼容。
- 负面：全局模式不再位于网络设置，老用户需要到应用分流页修改。
- 跟进：若以后决定强制策略，需要迁移现有全局名单为一份默认策略，并升级 WebDAV 字段。

## Alternatives Considered

- **保留设置入口并继续显示说明**：入口重复，用户仍会改到不生效的值。
- **删除全局回退，强制至少一份策略**：语义更单一，但要迁移现有数据、处理空状态和 WebDAV 兼容，超出本次范围。
- **只删设置入口，不提供全局模式编辑**：默认回退的模式将无法修改，功能退化。
