## r01-1
- 严重度：高
- 症状：隐藏系统应用时，全选、反选或从剪贴板导入会把已经选中、但当前列表里看不见的应用从策略里删掉。

## r01-4
- 严重度：中
- 症状：在访问控制或覆写设置里改完还没返回，旋转屏幕或切换深色模式后，这些修改消失。
- 代码：

- 为什么是问题：访问控制的已选应用只在 `defer` 里写回（`AccessControlActivity.kt` 第 64–70 行）。持久覆写和 Meta 功能覆写也只在 `defer` 里 `patchOverride`（`OverrideSettingsActivity.kt` 第 22–26 行，`MetaFeatureSettingsActivity.kt` 第 27–31 行）。`defer` 只由 `finish()` 调用。配置变更走 `onDestroy()`，这里 `cancel()` 关掉页面协程，不会调用 `finish()`。这三个页面的 `configChanges` 只有 `uiMode`（`AndroidManifest.xml` 第 166–174 行、第 186–188 行），旋转会直接销毁重建。深色模式虽然落在 `uiMode` 上，`onConfigurationChanged` 仍会 `recreate()`（第 149–152 行），同样不经过 `finish()`。重建后的页面从存储重新读取，旋转或切换深色前的勾选和覆写修改都还在内存里，没有写进去。
- 方向：配置变更和 `recreate()` 之前把访问控制选择和持久覆写写回存储，或放进实例状态，不要只靠 `finish()` 里的 `defer`。

## r01-5
- 严重度：中
- 症状：实时日志在内存里超过 128 条之后，界面上的增量更新会丢掉新行，只删掉旧行。
- 代码：
```17:46:app/src/main/java/com/github/kr328/clash/log/LogcatCache.kt
    suspend fun append(msg: LogMessage) {
        lock.withLock {
            if (array.size() >= CAPACITY) {
                array.removeFromStart(1)

                removed++
                appended--
            }

            array.addLast(msg)

            appended++
        }
    }

    suspend fun snapshot(full: Boolean): Snapshot? {
        return lock.withLock {
            if (!full && removed == 0 && appended == 0) {
                return@withLock null
            }

            Snapshot(
                List(array.size()) { array[it] },
                removed,
                if (full) array.size() + appended else appended
            ).also {
                removed = 0
                appended = 0
            }
        }
    }
```
- 为什么是问题：`LogcatActivity` 每 500ms 把 `messages`、`removed`、`appended` 交给 `patchMessages`，第一次用全量，之后用增量（`LogcatActivity.kt` 第 122–127 行）。缓冲未满时 `appended` 能数出新增条数。写满 128 条并已经做过一次快照后，每来一条新日志都会先 `appended--` 再 `appended++`，增量快照里的 `appended` 保持 0，`removed` 却按新日志条数增加。增量更新因此只删除旧行，不把新行附上。全量分支用的是 `array.size() + appended`：第一次快照前若已经有 N 条日志，报给界面的追加条数是 2N，而 `messages` 只有 N 条。
- 方向：环缓溢出时，只把界面已经见过的那一行计进 `removed`，把界面还没见过的新增计进 `appended`；全量快照的追加条数等于当前列表长度。
